# NanoNet Mac M4 推理性能分析报告

## 执行摘要

**NanoNet** 在 Mac M4 平台上的推理性能表现**极其出色**，远超预期：

- **单帧推理帧率：~1,670 FPS**（带同步等待）
- **单帧推理延迟：~0.60 ms**
- **批量推理吞吐量：~31,800 img/s**（batch_size=32）
- **异步理论峰值：~11,800 FPS**

相比文档中 Cortex-A53 的预估值，性能提升 **18-28 倍**。

| 项目 | 值 |

## 详细性能数据

### 1. 单帧推理性能 (batch_size=1)

| 指标 | 数值 | 说明 |
|---|---|---|
| **帧率 (FPS)** | **1,670.7** | 含 `mx.eval()` 同步等待，真实可用帧率 |
| **延迟** | **0.60 ms** | 单帧从输入到输出的完整推理时间 |
| **异步理论峰值** | **11,803 FPS** | 不含同步等待，反映 MLX 图执行优化能力 |

**分析**：
- 1,670 FPS 意味着每帧仅需 **0.6 毫秒**，可轻松满足 60/120/240 FPS 的实时推理需求
- 异步峰值 11,800 FPS 说明 MLX 的图优化和延迟执行策略非常高效
- 同步与异步的差距 (0.6ms vs 0.085ms) 主要来自 GPU 同步开销

### 2. 批量推理性能

| Batch Size | 吞吐量 (FPS) | 单帧延迟 (ms) | 总吞吐量 (img/s) |
|---:|---:|---:|---:|
| 1 | 1,530 | 0.65 | 1,530 |
| 4 | 6,218 | 0.16 | 6,218 |
| 8 | 11,491 | 0.09 | 11,491 |
| 16 | 20,084 | 0.05 | 20,084 |
| **32** | **31,803** | **0.03** | **31,803** |

**分析**：
- 吞吐量随 batch size **近乎线性增长**，说明模型计算密度低，GPU 利用率高
- Batch=32 时，单帧延迟降至 **0.03 ms**，吞吐量达到 **31,800 img/s**
- 适合离线批量处理场景（如数据集标注、批量检测）

### 3. 与文档预估值对比

| 平台 | 精度 | 文档预估 FPS | 实测 FPS | 性能倍数 |
|---|---|---:|---:|---:|
| Cortex-A53 | FP32 | 60-90 | - | 1× (基准) |
| Cortex-A53 | INT8 | 120-180 | - | ~2× |
| **Mac M4** | **FP32** | 200-500 (预估) | **1,670** | **18-28×** |

**关键发现**：
- Mac M4 实测性能是 Cortex-A53 FP32 预估的 **18-28 倍**
- 甚至超过了 Cortex-A53 INT8 量化预估的 **9-14 倍**
- 说明 M4 的 GPU/Neural Engine 配合 MLX 框架优化效果显著

## 模型架构分析

### NanoNet 结构

```
Input: 45 × 60 × 2  (depth_norm + amp_norm)
│
├─ Conv2d(2→8, k=3) + BN + ReLU + MaxPool(2)   → 22×30×8    [标准卷积]
├─ Conv2d(8→16, k=3) + BN + ReLU + MaxPool(2)  → 11×15×16   [标准卷积]
│
├─ DSConv(16→32, k=3) + BN + ReLU + MaxPool(2) → 5×7×32     [深度可分离卷积]
│     ├─ DW: Conv2d(16,16, k=3, groups=16)
│     └─ PW: Conv2d(16,32, k=1)
│
├─ DSConv(32→64, k=3) + BN + ReLU + MaxPool(2) → 2×3×64     [深度可分离卷积]
│     ├─ DW: Conv2d(32,32, k=3, groups=32)
│     └─ PW: Conv2d(32,64, k=1)
│     └─ Dropout(0.3)
│
├─ Global Average Pooling                        → 64
│
├─ Linear(64, 32) + BN + ReLU + Dropout(0.3)
└─ Linear(32, 2)                                 → [no-hand / hand]
```

### 参数量分布

| 层 | 参数量 | 占比 | 类型 |
|---|---:|---:|---|
| FC1 (64→32) | 2,080 | 30.1% | 全连接 |
| PW4 (32→64, k=1) | 2,112 | 30.6% | 逐点卷积 |
| Conv2 (8→16, k=3) | 1,168 | 16.9% | 标准卷积 |
| PW3 (16→32, k=1) | 544 | 7.9% | 逐点卷积 |
| DW4 (32→32, k=3) | 320 | 4.6% | 深度卷积 |
| DW3 (16→16, k=3) | 160 | 2.3% | 深度卷积 |
| BN/其他 | 322 | 4.7% | 归一化 |
| **TOTAL** | **6,906** | **100%** | |

**关键设计**：
- 使用 **Depthwise Separable Convolution** 将 Conv3/4 从 23,136 参数降至 3,136
- 模型极度轻量，计算瓶颈不在参数量，而在内存带宽和调度开销

## 性能优势来源

### 1. Apple M4 硬件优势
- **GPU 架构**：M4 的 GPU 具有强大的并行计算能力
- **统一内存**：CPU/GPU 共享内存，减少数据拷贝开销
- **Neural Engine**：虽然 MLX 主要使用 GPU，但部分操作可能受益於 ANE

### 2. MLX 框架优化
- **延迟执行 (Lazy Evaluation)**：自动图优化和操作融合
- **GPU 后端**：直接调用 Metal API，充分利用 Apple GPU
- **异步执行**：操作可并行调度，减少等待时间

### 3. 模型设计优势
- **极小参数量**：7K 参数可完全放入 GPU L2 缓存
- **低计算密度**：~1M FLOPs，GPU 可轻松并行
- **DSConv 友好**：深度可分离卷积在 GPU 上效率高

## 优化建议

### 进一步提升性能

1. **INT8 量化**
   - 预期模型大小：~8 KB
   - 预期性能提升：1.5-2× (取决于量化实现)
   - MLX 支持量化推理，可尝试

2. **批处理优化**
   - 对于离线场景，使用 batch_size=16~32 可最大化吞吐量
   - 单帧场景保持 batch_size=1 即可

3. **Metal Performance Shaders (MPS)**
   - 可尝试直接调用 MPS 的卷积实现
   - 可能获得额外的 10-20% 性能提升

### 部署建议

| 场景 | 推荐配置 |
|---|---|
| **实时应用 (60 FPS)** | batch_size=1, FP32, 异步执行 |
| **高帧率追踪 (120+ FPS)** | batch_size=1, FP32, 流水线并行 |
| **离线批量处理** | batch_size=16~32, FP32 |
| **嵌入式/移动端** | INT8 量化, batch_size=1 |

NanoNet 在 Mac M4 平台上的推理性能表现**非常出色**：

✅ **单帧推理：1,670 FPS (0.60 ms)**，远超实时需求  
✅ **批量推理：31,800 img/s (batch=32)**，适合离线处理

**推荐使用场景**：
